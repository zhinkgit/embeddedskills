# 嵌入式 C 编码规范（团队版草案）

> 本文件是 `codecheck` skill 的"写码前指南"，目标是把规范变成 AI 和人都能直接执行的条目。
> 条款尽量与 MISRA C:2012 / CERT C 对齐，但这里是**摘要与工程约定**，不是标准原文；正式评审以标准条款和项目《软件设计规范》为准。
> 每条都尽量给出"怎么写 / 为什么 / 怎么查"。

## 0. 适用范围

- 适用于 MCU 上的 C 代码：应用层（APP）、板级支持（BSP）、协议栈（NET）、驱动与工具库（LIB）。
- 第三方代码（CMSIS、HAL、RTOS、portable）不强制改造，但新增封装层必须遵守本规范。
- 生成代码（EIDE/Keil 自动生成、RTE 配置生成）不手改；需要调整时改生成源或配置。

## 1. 类型与数值

1. **固定宽度类型**：协议字段、寄存器、持久化数据、跨模块接口一律使用 `<stdint.h>` 的 `uint8_t/uint16_t/uint32_t/int32_t`；`int` 只用于局部循环计数。
2. **禁止隐式窄化**：把宽类型赋给窄类型前必须做范围检查并显式转换；禁止依赖编译器截断。
3. **有符号/无符号不混算**：长度、索引统一用 `size_t` 或 `uint32_t`；比较前确认类型一致，避免 `int` 与 `unsigned` 比较。
4. **枚举有明确底层类型**：通信协议/状态机枚举显式指定 `uint8_t` 等底层类型，禁止依赖编译器默认 `int`。
5. **布尔语义清晰**：布尔量用 `bool`（`<stdbool.h>`）或 `uint8_t` 的 0/1，禁止用 `-1/1` 表示真假。

## 2. 内存与资源

1. **禁止动态内存**：不使用 `malloc/calloc/realloc/free`；用静态数组、内存池或启动期一次性分配，并给出容量上界与耗尽策略。
2. **缓冲区有界**：所有拷贝/拼接使用带长度参数的接口；禁止 `strcpy/strcat/sprintf/gets`，改用 `snprintf`、显式长度拷贝。
3. **所有权明确**：谁分配、谁释放、生命周期到哪；跨模块传递指针时在注释中写清"借用/拥有"。
4. **资源成对释放**：文件、socket、CAN/串口句柄、Flash 锁在错误路径上也要释放；优先用统一 cleanup 出口。

## 3. 错误处理

1. **有返回值必须处理**：驱动、协议、存储、通信调用一律检查返回值；确需忽略时写 `(void)` 并注释原因。
2. **错误码集中定义**：每个模块定义自己的错误码枚举/宏，禁止到处返回裸 `-1` 而不区分原因。
3. **不吞错误**：底层失败向上传递或记录日志；禁止 `catch/except: pass` 式静默（C 里对应"忽略返回值 + 不记录"）。
4. **断言用于不可恢复错误**：参数非法、状态机不可能分支用 `assert`（release 下需确认宏行为）；对外部输入用返回值而不是断言。
5. **初始化失败必须可见**：外设/时钟/Flash/通信初始化失败时返回错误并让上层决定是否进入安全状态，禁止"初始化失败继续跑"。

## 4. 控制流

1. **禁止递归**（MISRA C:2012 Rule 17.2）：改为迭代或显式栈；确需递归时给出最大深度与栈占用分析。
2. **禁止 goto**：仅允许向函数末尾统一 `cleanup` 标签跳转，且不得跳过变量初始化（MISRA Rule 15.1-15.3 的精神）。
3. **控制语句必须带花括号**（MISRA Rule 15.6）：`if/else/for/while/do` 即使只有一行也加 `{ }`。
4. **switch 必须有 default**：每个 `case` 以 `break/return` 结束，禁止贯穿（除非显式注释 `/* fall through */`）。
5. **循环有界**：`while` 循环必须有退出条件或超时；等待硬件标志必须带超时与失败返回，禁止死等。
6. **函数单一职责**：单函数不超过 50 行、圈复杂度不超过 10；超限时拆成静态子函数并补测试。

## 5. 并发与 volatile

1. **volatile 只用于**：硬件寄存器、ISR 与主循环共享的标志/计数器。普通变量禁止滥用 `volatile` 掩盖竞态。
2. **ISR 短小**：ISR 内只做置标志/搬数据/清中断，禁止阻塞、浮点、动态内存、长时间循环。
3. **共享数据有保护**：多字节共享变量用临界区或原子操作；临界区尽量短，禁止在临界区内调用可能阻塞的函数。
4. **内存序/编译器屏障**：涉及 DMA、双缓冲、无锁队列时明确使用屏障（`__DMB()` 等），并在注释中写清生产者/消费者关系。

## 6. 指针与硬件访问

1. **寄存器用 volatile 指针**：`volatile uint32_t *reg = (volatile uint32_t *)REG_BASE;` 禁止把地址存成普通整数再转换。
2. **指针/整数转换用 `uintptr_t`**：必须转换时显式用 `uintptr_t` 并限定用途（MISRA Rule 11.4/11.6）。
3. **指针使用前判空**：对外接口的指针参数判空并返回错误；内部不变量可用断言。
4. **const 正确性**：只读参数加 `const`；返回内部缓冲区的接口在注释中说明有效期与是否可修改。

## 7. 预处理与头文件

1. **include guard 不用保留标识符**：用 `#ifndef ORDER_CONFIG_H`，禁止 `__ORDER_CONFIG_H`（CERT DCL37-C；MISRA Rule 21.1 相关）。
2. **宏参数加括号**：`#define MAX(a, b) (((a) > (b)) ? (a) : (b))`；能用 `static inline` 函数就不用宏。
3. **头文件最小暴露**：只在头文件放对外声明；内部函数/变量加 `static`；禁止在头文件定义变量（用 `extern` + .c 定义）。
4. **include 顺序**：自身头文件 → C 标准库 → 平台/RTOS → 项目公共头 → 本模块头；避免头文件互相包含成环。

## 8. 命名与注释

1. **模块前缀**：导出符号用 `<module>_` 前缀（如 `order_init`、`bsp_flash_read`），避免链接期撞名。
2. **大小写风格统一**：类型 `PascalCase`（或项目既定风格）、函数/变量 `snake_case`、宏 `UPPER_SNAKE_CASE`；同一工程只允许一种风格。
3. **单位写进名字或注释**：`timeout_ms`、`delay_us`、`voltage_mv`；禁止 `timeout` 这种无单位命名。
4. **文件头**：模块职责、作者/维护者、创建日期、对外接口概述；修改记录可放版本库，不必堆在文件头。
5. **注释解释"为什么"**：寄存器位含义、时序约束、协议字段来源、魔数出处；不要复述代码"做了什么"。
6. **禁止注释掉的代码**：删除而不是注释；需要保留历史用版本库。

## 9. 结构与可测性

1. **模块边界清晰**：驱动只依赖 HAL/寄存器，不直接依赖 APP；APP 通过接口层访问驱动，便于替换与测试。
2. **静态函数可测**：核心算法拆成纯函数/静态函数，输入输出明确；需要测试时通过测试专用头文件暴露。
3. **状态机显式化**：复杂流程用 `enum` 状态 + `switch`，每个状态的处理函数独立，禁止用深层嵌套 `if` 表达状态。
4. **配置与代码分离**：引脚、波特率、超时、容量等放配置头/结构体，禁止散落魔数。

## 10. 提交前检查清单

- [ ] `codecheck check --fail-on warning` 通过（或新增违规已进入 baseline 并写明理由）。
- [ ] 构建日志 0 error / 0 warning（CC-014）。
- [ ] 新增/修改函数有明确错误路径与超时。
- [ ] 新增对外接口有注释（参数、返回值、副作用、线程/中断上下文）。
- [ ] 没有新增 `malloc`、`strcpy`、裸 `-1` 错误码、无界循环。
- [ ] 与规范冲突但确需保留的写法，已在代码注释和 baseline 中记录原因与到期时间。
